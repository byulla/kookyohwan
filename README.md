# 구교환 (求교환)

수강신청 정정기간에 정원이 마감된 교양 과목을 **1:1로 교환할 상대를 찾아 주는 콘솔 프로그램**.
교환 요청을 한 곳에 모아 두고, 조건이 교차 일치하는 상대를 찾은 뒤 시간표가 겹치는 후보는 사유와 함께 제외한다.

- 내가 내놓는 과목 = 상대가 원하는 과목, 상대가 내놓는 과목 = 내가 원하는 과목인 요청만 후보
- 받을 과목이 내 시간표와 겹치면 제외 (내놓는 과목 자리는 비므로 비교에서 뺌)
- 상대가 내 과목을 받았을 때 상대 시간표와 겹쳐도 제외
- 한 학기 최대 18학점. 넘게 되는 과목 추가·교체는 거절하고, 교환 후 18학점을 넘는 상대도 제외 (예외 없음)
- 시간표는 처음에 '편집 중' 상태로, 지금 듣는 과목을 과목 목록에서 넣은 뒤 저장(확정)한다
- 확정한 뒤에는 빈자리가 있는 과목만 바로 수강신청할 수 있고, 마감된 과목은 교환 요청으로만 얻는다
- 매칭은 조회 전용. 합의와 정정은 프로그램 밖에서 한다

과목 목록은 가천대학교 2026학년도 2학기 개설 과목 3,242개이고, 학수번호와 교과목명을 학교 시간표 그대로 쓴다.

## 실행 환경

| 항목 | 내용 |
|---|---|
| Java | JDK 17 이상 (`java -version`, `javac -version`으로 확인). 외부 라이브러리 없음 |
| 작업 폴더 | `data/courses.csv`처럼 상대 경로로 읽으므로 **프로젝트 루트(`kookyohwan/`)에서 실행**. IDE는 Working directory를 루트로 |
| 문자 인코딩 | 소스·데이터 모두 UTF-8. 컴파일 시 `-encoding UTF-8` 필수 |
| 터미널 폭 | 100칸 이상 권장 (표가 줄바꿈되지 않게). 주말 수업을 시간표에 넣으면 격자가 110칸 |

## 실행 명령

Mac / Linux

```bash
cd kookyohwan
find src -name "*.java" > sources.txt
javac -encoding UTF-8 -d out @sources.txt
java -cp out kookyohwan.Main
```

Windows (cmd)

```bat
cd kookyohwan
dir /s /b src\*.java > sources.txt
javac -encoding UTF-8 -d out @sources.txt
chcp 65001
java -Dfile.encoding=UTF-8 -cp out kookyohwan.Main
```

GUI(Swing)로 실행하려면 마지막 줄만 바꾼다. 외부 라이브러리는 없고, 콘솔과 같은 데이터 파일을 쓴다.

```bash
java -cp out kookyohwan.GuiMain
```

탭은 4개다: 내 시간표, 과목 목록, 교환, 전체 요청.
교환 탭 왼쪽에서 요청을 등록하거나 고르면 오른쪽에 교환할 수 있는 상대가 바로 나오고, 상대 카드의 [교환 확정]을 누르면 시간표에서 과목이 맞바뀌고 요청이 매칭완료가 된다(GUI 전용). 둘이서 하는 교환과 세 명이 돌려서 하는 교환이 같은 목록에 나온다.
전체 요청 탭은 내 과목을 희망하는 요청을 맨 위에 색칠해 보여 주고, 줄에 마우스를 올리면 그 요청과 교환할 방법을 알려 준다.
사용자 전환은 오른쪽 위 버튼. 저장 버튼은 없고 바뀔 때마다 자동으로 저장한다.

시작하면 학번을 묻는다. 준비 데이터의 기본 사용자는 조혜라(`202633781`).
등록되지 않은 학번을 넣으면 이름을 받아 빈 시간표로 시작한다.

다른 데이터 폴더로 실행하려면 폴더 이름을 인자로 준다.

```bash
java -cp out kookyohwan.Main data-ac8
```

## 메뉴

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | 과목 목록 보기 | 교과목명 일부나 학수번호 앞자리로 검색 (최대 30줄). 과목마다 빈자리 또는 마감 표시 |
| 2 | 내 시간표 보기 / 과목 추가 | 요일 x 교시 격자. 편집 중: 학수번호로 넣고 `저장`으로 확정. 확정 후: 빈자리 있는 과목만 수강신청. `-학수번호`로 과목 빼기. 겹치면 교체 여부 확인 |
| 3 | 교환 요청 등록 | 내놓을 과목(내 시간표의 교양) 번호 + 희망 과목명(분반 무관, 학수번호를 넣으면 과목명으로 변환) |
| 4 | 교환 요청 목록 보기 | 전체 요청과 상태. 내 요청은 `<- 내 요청` 표시 |
| 5 | 매칭 실행 | 내 대기 요청(2건 이상이면 번호 선택)에 맞는 상대를 `[가능]`/`[제외]`와 사유로 출력 |
| 9 | 사용자 전환 | 저장한 뒤 학번을 다시 입력 |
| 0 | 저장하고 종료 | `students.csv`, `requests.csv`를 다시 쓰고 종료 |

하위 입력에서 빈 줄(Enter)을 넣으면 메뉴로 돌아간다.

## 데이터 파일 (`data/`)

UTF-8, 첫 줄은 헤더, 구분자는 쉼표. 한 칸에 값이 여러 개면 세미콜론(`;`). 값 안에 쉼표가 있으면 큰따옴표로 감싼다.

| 파일 | 형식 | 예 | 읽기·쓰기 |
|---|---|---|---|
| `courses.csv` | 코드,과목명,분반,구분,시간,교수,강의실,학점,정원,수강인원 | `08306001,운영체제,001,MAJOR,목4-5;금3,오기욱,AI관-209,3,60,60` | 읽기 전용. 없으면 안내 후 종료 |
| `students.csv` | 학번,이름,과목코드,시간표상태 | `202633781,조혜라,09392004;08306001;05306002,CONFIRMED` | 메뉴 0·9에서 저장. 없으면 빈 상태로 시작 |
| `requests.csv` | 번호,학번,내놓는과목코드,희망과목명,상태 | `1,202612346,11393006,프랑스어1,WAITING` | 메뉴 0·9에서 저장. 없으면 빈 상태로 시작 |

- 코드 = 학수번호 8자리, 분반 = 학수번호 끝 3자리, 과목명 = 교과목명 그대로
- 시간 `월3-4` = 월요일 3교시부터 4교시까지, `금3` = 금요일 3교시. 요일은 월~일, 교시는 1~14
- 구분: `MAJOR`(전공: 전필·전선) / `GENERAL`(교양: 교필·교선·계교) / `TEACHING`(교직) / `MILITARY`(군사). 교환 요청은 교양만 가능
- 상태: `WAITING`(대기) / `MATCHED`(매칭완료) / `CANCELLED`(취소). 시간표상태: `EDITING`(편집 중) / `CONFIRMED`(확정). 칸이 없으면 과목이 있는 학생은 확정으로 본다
- 빈자리 = 정원 - (수강인원 + 이 프로그램에 등록된 학생 중 그 과목을 듣는 사람 수). 정원이 0이면 제한 없음
- **정원은 학교 시간표 그대로지만 수강인원은 실제 값이 아니다.** 시연용으로 만든 값이다(약 1/3이 마감). 생명과 나눔·프랑스어1·일본어1은 전 분반 마감으로 두었다
- 복원 순서는 courses -> students -> requests. 형식이 틀린 줄이 있으면 파일명과 줄 번호를 알려 주고 종료한다
  (일부만 읽고 계속하면 종료할 때 파일을 덮어써서 그 줄이 사라지기 때문)

`courses.csv`는 `src/kookyohwan/docs/`의 학교 시간표 엑셀 4개(교양 1,329 / 전공 1,886 / 교직 23 / 군사 4)를 변환한 것이다.

## 폴더 구조

```
kookyohwan/
├── data/            준비 데이터 + 저장 파일 (CSV)
├── data-ac8/        AC8 시연용 데이터
├── data-swap3/      세 명 교환 시험용 데이터 (`java -cp out kookyohwan.GuiMain data-swap3`, 학번 202630001)
├── test/            테스트 5개 (JUnit 없이 main으로 실행): ConflictTest, ScenarioTest, EdgeCaseTest, CycleTest, WeirdTest
├── src/kookyohwan/
│   ├── Main.java    콘솔 진입점: 복원 -> 학번 입력 -> 메뉴 -> 저장
│   ├── GuiMain.java GUI 진입점 (Swing)
│   ├── gui/         Swing 화면: MainPanel, TimetableCanvas, CoursePanel, ExchangePanel, RequestPanel 등
│   ├── model/       Day, TimeSlot, Course, Timetable, Student, SwapRequest, MatchResult, CycleMatch 등
│   ├── service/     Repository<K, V>, CourseCatalog, StudentRegistry, RequestBoard, MatchService, ExchangeService, EnrollmentService
│   ├── storage/     Storage 인터페이스, FileStorage(CSV)
│   ├── ui/          ConsoleUI, TimetableGrid, TextUtil
│   └── docs/        개발 계획서(plan.pdf), 학교 시간표 엑셀 원본
└── out/             javac 결과 (제출 제외)
```

의존 방향은 `ui -> service -> model`, `storage -> model`. 저장 구현체(`FileStorage`)는 `Main`만 안다.
겹침 판정은 `Timetable.findConflicts` 한 곳이고, 시간표 추가·매칭(내 쪽)·매칭(상대 쪽)이 모두 이 메소드를 부른다.
